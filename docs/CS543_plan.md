## 1. 项目目标与要回答的问题

项目要回答的主问题是：不训练任何模型的经典图像处理流程，在太阳暗条实例分割上能达到多高的 PQ？这个分数要和人（在相同参照下的标注者，见 3.4）以及一个小 U-Net 参照对比。

**贡献定位（和 proposal 一致）**：经典暗条检测已有二十年历史（Shih & Kowalski 2003、Qu et al. 2005、Fuller et al. 2005、Bernasconi et al. 2005），所以我们不声称提出新检测器。新的是评估：在多站、多人标注的数据上用实例级指标打分，在相同参照下和人对比，按类型和面积拆解误差，并估计漏标的影响。

## 3. 评估协议

主指标是 PQ，匹配规则和组织者的自评 notebook 完全一致。其他指标用来解释 PQ 为什么变化。

**3.1 匹配与 PQ**

- 预测的对象是一张观测图；真值的对象是一套标注。一张图有几套标注，就拿同一份预测分别和每套标注比较一次。所有比较的 TP、FP、FN 汇总后计算 PQ。
- 一个预测和一条真值的 IoU > 0.5 时算作匹配（TP）。阈值取 0.5 时，每条真值最多匹配一个预测，不需要做二分图匹配。
- 公式：

```latex
PQ = \frac{\sum_{(p,g)\in TP} IoU(p,g)}{|TP| + \tfrac12|FP| + \tfrac12|FN|} = \underbrace{\frac{\sum IoU}{|TP|}}_{SQ} \times \underbrace{\frac{|TP|}{|TP| + \tfrac12|FP| + \tfrac12|FN|}}_{RQ}
```

- 同时报告 SQ（匹配上的实例的平均 IoU，衡量边界准不准）和 RQ（衡量实例是否找对），用来判断 PQ 的变化来自哪一部分。
- 没有暗条的标注套（共 154 套）也参与评估：对这些套来说，图上的所有预测都算 FP。
- **核对评估器**：我们的评估器用 pycocotools 的 RLE IoU 计算，速度快。上线前在 20 张图上和官方 notebook 的 torch 实现对比，要求 PQ 完全一致。

**3.2 辅助指标**

- 像素级 Dice：只看二值前景，不区分实例。这个指标用来把“像素分对了但实例划错了”和“像素本身就分错了”两种情况分开。
- 一对多和多对一的数量：只要 IoU > 0 就算有重叠，统计官方 notebook 里的 1:n 和 n:1 分布。
- 处理速度：每张图在笔记本 CPU 上的处理时间（中位数和最大值）。
- **IoU > 0.3 的 PQ**（稳健性检查）：细长暗条在 IoU > 0.5 下对边界画法很敏感，所以另算一版 IoU > 0.3 的 PQ。阈值低于 0.5 时匹配不再唯一，要用匈牙利算法做一对一匹配。只看方法之间的排名是否改变。
- **按面积分档的召回率**：按 3.3 节的 3 个面积档分别统计召回，重点报告最大一档（> 2,400 像素，约前 25%），因为对空间天气最重要的是大暗条。这一项用来回答“结果是否有用”。

**3.3 误差分类（覆盖全部 FP 和 FN，不重叠）**

| 类别 | 定义 | 计入 |
| --- | --- | --- |
| 漏检 | 真值没有和任何预测重叠（IoU = 0） | FN |
| 碎片化 | 真值没有匹配上，但和 ≥ 2 个预测重叠 | FN，另有相关的 FP |
| 定位偏差 | 真值只和 1 个预测重叠，但 IoU ≤ 0.5 | FN，另有相关的 FP |
| 过度合并 | 预测没有匹配上，但和 ≥ 2 条真值重叠 | FP |
| 孤立误检 | 预测没有和任何真值重叠 | FP |

每类再按真值或预测的面积分成 3 个 bucket（< 600、600–2,400、> 2,400 像素，大致对应面积的 25% 和 75% 分位）统计。

**3.4 参照上限与统计显著性**

- **标注者之间的 PQ**：在多人标注的图上，把一套标注当作预测、另一套当作真值。PQ 对两套标注是对称的，所以每对只算一次。全数据集上已经算出 0.329（860 对）。
- **0.329 不是上限**：方法的预测要和每一套标注分别比较。一个接近“平均标注”的预测，对每个标注者的分数可能都高于标注者之间的分数。所以不能把“超过 0.329”解读成“超过人”。
- **人和方法在相同参照下对比（主要的人机比较）**：只用测试集里多人标注的图（约 120 张）。每张图轮流留出一名标注者，把留出的标注者和方法都拿去和其余标注者比较，TP/FP/FN 分别汇总，得到“人的 PQ”和“方法的 PQ”。两者用的参照和图完全相同，差值用配对 bootstrap 给出 95% 区间。只有 2 名标注者的图，人的分数就等于这两人之间的 PQ。
- **置信区间**：以观测图为单位做 1,000 次 bootstrap（有放回重采样），给出 PQ 的 95% 区间。比较两个配置时用配对 bootstrap：每次重采样都用同一批图算两个配置的 PQ 差，再看差值区间是否包含 0。

## 4. 要实现的方法：经典流程

流程由 7 个顺序执行的模块（M0–M6）组成，每个模块针对一种具体的失败类型。每个模块都保留一个最简单的版本（a），用作消融实验的对照。未调参的基线（PQ 0.08–0.10）由 M0、M1c、M3a、M4 的开运算和面积过滤、M5a 组成。

1. **M0 日面 mask**。输入灰度图，输出日面圆和二值 mask。做法：Otsu 阈值 → 最大连通域 → 最小外接圆，半径内缩 ρ。参数：ρ ∈ {2%, 3%, 5%}。针对：日面边缘白圈和角落文字产生的误检。
2. **M1 背景校正**。输出亮度比图 R = I / B，其中 B 是估计出的低频亮度背景。版本：
    - (a) 不做校正，B 取日面内亮度中位数；
    - (b) 径向剖面，B 取同一半径圆环内的中位数；
    - (c) 大核中值滤波，在 512×512 分辨率上计算后上采样。

    参数：中值核 k_bg ∈ {15, 31, 63}（按 512 分辨率计）。针对：亮度不均匀，这是全局阈值产生误检和漏检的主要原因。
3. **M2 去噪**。对 R 做高斯平滑，σ ∈ {0, 1, 2} 像素。针对：日面上的细粒纹理产生的碎点。
4. **M3 候选暗区提取**。输出二值候选 mask。版本：
    - (a) 单阈值 R < t；
    - (b) 滞后阈值：以 R < t_high 的像素为种子，只保留与种子连通、并且 R < t_low 的区域；
    - (c) 在 (b) 的基础上，用 Frangi 线状滤波（检测暗色脊线，Hessian 尺度 s ∈ {2, 4, 8}）的响应作为第二个条件。

    参数：t、t_low、t_high ∈ [0.85, 0.96]，Frangi 响应阈值 f。针对：细 barb 和暗条两端的低对比度部分被漏掉，导致暗条断开。
5. **M4 形态学清理与形状过滤**。依次做开运算（半径 r_o）和闭运算（半径 r_c，用来连接很小的断口），然后去掉面积 < A_min 的连通域。再加一个形状过滤：去掉长短轴比 < e_min 的圆形暗区。太阳黑子就是这类暗区，叠加图上已经观察到未标注的黑子。参数：r_o ∈ {1, 2}，r_c ∈ {0, 2, 4}，A_min ∈ {300, 600, 1000, 2000}，e_min ∈ {1, 2, 3}。针对：孤立误检。
6. **M5 实例化**。输出实例列表。版本：
    - (a) 8 邻域连通域；
    - (b) 在 (a) 的基础上合并碎片：两个连通域的最近距离 ≤ d，并且主方向（用骨架做 PCA 得到）夹角 ≤ θ 时合并；
    - (c) 在 (b) 的基础上拆分粘连：对面积大或骨架有分叉的连通域，用距离变换加分水岭拆分。

    参数：d ∈ {10, 20, 40} 像素，θ ∈ {20°, 40°}。针对：碎片化和过度合并，PQ 对这两类错误都扣分。
7. **M6 边界调整**。对每个实例膨胀 k ∈ {0, 1, 2, 3} 像素。标注多边形的边界可能比阈值结果宽，这一点是推断，由 E2 验证。针对：SQ 偏低，以及 IoU 刚好低于 0.5 而匹配失败。

**调参方式**

如果对全部参数做完整的网格搜索，组合数会达到上万，按每张图约 0.2 秒、调参集 670 张计算，笔记本跑不完。所以改用分阶段的坐标搜索：

1. 先在调参集里随机抽 150 张图。按 M1 → M3 → M4 → M5 → M6 的顺序逐个模块搜索，其余模块的参数固定在当前最优值；这样重复 2 轮。
2. 取 PQ 最高的 5 组配置，在完整调参集上复核，选出最终配置。
3. 把不依赖后续参数的中间结果缓存到磁盘（M0 的日面 mask、M1 的亮度比图），并用 4 个进程并行。

预计全部调参要跑 100–150 组配置，在笔记本上共约 1–3 小时（推断，未实测）。

## 6. U-Net 对照（E7a 最小目标，E7b 最大目标）

目的是回答：只把“每个像素是不是暗条”这一步换成训练出来的网络时，PQ 能提高多少。实例化和评估部分与经典流程完全相同。没有这个参照，就分不清和人的差距是“经典方法”造成的，还是任务和标注噪声本身造成的。

**6.0 两档配置**

| 项 | E7a（最小目标） | E7b（最大目标） |
| --- | --- | --- |
| 输入分辨率 | 512×512 | 1024×1024，并保留 512 作分辨率对照 |
| 损失函数 | 只用 L1 | L1 和 L2 |
| 随机种子 | 1 个 | 每种损失 3 个 |
| 算力 | 不超过 1 GPU 小时（推断） | 约 6 GPU 小时（推断） |
| Kaggle 不可用时 | 改用 ResNet-18 编码器、减少 epoch，在笔记本 CPU 上训练（预计几小时，未实测） | 放弃 |

下表是两档共用的设置；分辨率、损失和种子数以上表为准。

**6.1 设置**

| 项 | 设定 |
| --- | --- |
| 模型 | segmentation-models-pytorch 的 U-Net，编码器 ResNet-34，用 ImageNet 预训练权重；单通道输入，单通道输出概率图 |
| 输入 | 先用 M0 去掉日面外的区域，再缩放到 1024×1024；另跑一组 512×512 用来量化分辨率的影响 |
| 标签 | 训练时，多人标注的图每个 epoch 随机选一套标注，把其中所有暗条合并成二值 mask。这样每个训练标签都来自单名标注者，和按单套标注评估的方式一致 |
| 损失函数 | L1 = Dice + BCE；L2 = Dice + BCE + 0.5 × soft-clDice（soft-clDice 是基于可微骨架的连通性损失，取自 jocpae/clDice 仓库） |
| 数据增强 | 水平、垂直翻转，90° 旋转，小幅亮度和对比度变化 |
| 训练 | Adam，学习率 3×10⁻⁴，batch 4，最多 50 个 epoch。早停依据是验证集上的 PQ，即把网络输出送入 M4 和 M5 之后算出的 PQ，而不是像素损失 |
| 重复次数 | E7a 跑 1 个种子；E7b 每种损失函数跑 3 个随机种子 |
| 算力 | Kaggle Notebooks 的免费 GPU。预计每次训练不超过 1 小时；E7a 共 1 次，E7b 共 6 次，约 6 GPU 小时（推断，未实测）。数据以私有 Kaggle Dataset 的形式上传 |

**6.2 推理与公平比较**

1. 概率图上采样回 2048×2048，按阈值 τ 二值化。
2. 二值结果接入和经典流程相同的 M4（形态学和形状过滤）、M5（实例化）、M6（边界调整）。
3. τ 以及 M4–M6 的参数都重新调，而且只用验证集。比较时两种方法只在“产生像素 mask”这一步不同。
4. 另做一组对照：U-Net 输出只接 M5a（8 邻域连通域）。这组用来确认经典的实例化规则对网络输出是否仍然有效。
5. 报告三项对比：L1 与 L2 的碎片化数量；U-Net 与经典流程的 PQ（配对 bootstrap）；两者在 CPU 上的推理耗时。

## 8. 风险与应对

| 风险 | 影响 | 提前检查的方式 | 应对 |
| --- | --- | --- | --- |
| 自己实现的评估器和官方规则不一致 | 所有数字都不可信 | 在 20 张图上和官方 notebook 对比 PQ | 不一致时以官方实现为准，官方实现只是慢一些 |
| 某些观测站的日面圆拟合失败（例如 Big Bear 日面外的灰色环） | 边缘产生大量误检 | 每个站抽 10 张图，把拟合出的圆叠加到图上检查 | 改用 Hough 圆检测，或者按站设定 Otsu 阈值的偏移 |
| 实例化规则改善了碎片化，却增加了过度合并 | PQ 提升有限 | E2 和 E4 里单独统计两类错误的数量 | 合并条件加上沿连线的平均亮度阈值，只在两段之间也是暗区时才合并 |
| 标注不完整导致误检偏多 | PQ 被低估，结论解释变难 | E5 人工抽查 | 报告修正后 PQ 的上下界；把这一点写进 Discussion，作为数据本身的特点 |
| 经典流程最终仍远低于 0.33 | 结果是负面的 | E1 每改一版都记录调参集 PQ | 课程允许负面结果；重点放在 E2、E4、E5 的分析，说明差距来自哪里 |
| 调参在笔记本上太慢 | 实验做不完 | 先测 1 组配置在 150 张图上的耗时 | 缓存 M0 和 M1 的结果；在 1024 分辨率上调参，最终配置再在 2048 上复核 |
| Kaggle GPU 额度不够或无法使用 | E7a 属于最小目标，会受影响；E7b 也受影响 | 第一周完成手机号验证，先跑 1 个 epoch 测耗时 | E7a 改用 ResNet-18、减少 epoch，在笔记本 CPU 上训练；E7b 直接放弃 |
| 组员人工判断漏标不可靠（不是领域专家） | E5 的修正区间可信度低 | 打标签前先一起读 MAGFiLO 的标注说明，并用 10 个样本校准 | 以“被其他标注者标过”的客观统计为主要证据，人工标签只写成敏感性分析 |
| 数据许可 | 数据的使用方式不合规 | — | MAGFiLO 是 CC BY-NC 4.0，课程使用属于非商业用途；上传到 Kaggle 时用私有 Dataset；报告里注明出处 |
