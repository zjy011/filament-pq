# Full experiment run

The GPU environment is PyTorch 2.11.0 + CUDA 12.8 on the local RTX 4060 Laptop
(8 GB). `requirements-tested.txt` records the installed versions. Install the
CUDA Torch wheels from the official PyTorch index before installing the project:

```powershell
python -m pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -e ".[dev,unet,report]"
```

`configs/study.yaml` fixes the experiment recipes before held-out evaluation.
The classical search uses 150 tune observations, two coordinate rounds and full
671-observation reranking of five finalists. E7a uses 606 training and 65
validation observations, ResNet34/ImageNet, 512 pixels, Dice+BCE, Adam 3e-4,
batch 4 and validation-PQ early stopping (patience 8, at most 50 epochs).

Two queues can run in separate terminals. They checkpoint progress to local
`results/study_logs/`; the same command skips completed outputs and resumes
unfinished supported jobs. Do not start duplicate copies of a queue.

```powershell
python -m scripts.complete_study --phase classic --extensions
python -m scripts.complete_study --phase learned --extensions
```

`--wait-existing` is only for attaching a queue to an already-running full
classical search or E7a training job. Omit it when restarting after shutdown.
The main classical test and blind-review packages are produced before the longer
sensitivity and cross-site experiments. Learned models select every threshold
and M4-M6 parameter using validation data only.

E7b uses 1024 pixels and seeds 543/544/545 for each of L1 (Dice+BCE) and L2
(L1 + 0.5 soft-clDice). Both 512- and 1024-pixel formal runs use true batch 4,
without gradient accumulation. A capacity test with batch 4 and L2 used a peak
6.918 GiB allocated / 7.008 GiB reserved, and a real-data two-step training smoke
test passed. The earlier microbatch-1 prototype is preserved under
`results/development_unet_1024_microbatch1_L1_543/` and excluded from formal
comparisons. This hardware-only amendment preceded every E7b test evaluation.
clDice uses the official foreground
formulation and ten skeleton iterations; its license is in
`THIRD_PARTY_NOTICES.md`.

E6 classical runs fix the untuned pipeline and retune only threshold and area
on the five available sites. This avoids importing full-pipeline parameters
selected using the excluded site. A matching restricted search on the main
split provides its in-distribution comparator. E6 U-Net retrains from ImageNet
for every excluded site, using that split's own train/val IDs.

## Interruption and reproducibility

- Training saves `best.pt`, resumable optimizer/scaler/RNG state in `last.pt`,
  `history.json` and `progress.json`. An interrupted epoch restarts from the
  previous completed epoch with deterministic data order and augmentation.
- Tuning saves trials and finalists. `--resume` checks the original dataset,
  split, starting configuration and search settings.
- Evaluation saves raw per-observation results. `--resume` checks the exact
  evaluation source digest, numerical packages, dataset, split, configuration
  and checkpoint. A completed test result is never recomputed; identical
  configurations reuse their original run with an explicit `reused_run.json`.
- Output JSON and checkpoints use atomic replacement. Raw data, caches,
  checkpoints, per-image results and reviewer packages remain outside Git.
- Queue subprocesses use `scripts.resilient_io` to retry brief Windows sharing
  violations during atomic file replacement. Permanent permission errors still
  fail. This I/O-only wrapper preserves the numerical evaluator's source digest,
  so an interrupted test resumes without relaxing the compatibility check.
- A powered-off or sleeping laptop cannot keep these local jobs running.
  Resume with the commands above; do not edit evaluation code during a partial
  test run. Existing configuration choices must remain frozen.

## Independent E5 review

The final-classical queue writes `results/blind_review_100/reviewer_a.zip` and
`reviewer_b.zip`. Give each reviewer only their ZIP. Each contains the same
100 anonymous crop pairs (original / candidate outline), a local HTML labeling
page and a blank CSV. Neither contains source observations, configuration
identifiers, other annotators' masks or the curator key.

Reviewers unzip, open `index.html`, label independently and export their CSV.
Human judgments are never generated by the program. After both files return:

```powershell
python -m scripts.summarize_reviews --package results/blind_review_100 --reviewer-a completed_a.csv --reviewer-b completed_b.csv --out results/manual_review.json
```

The summary reports category counts, agreement, Cohen's kappa and two explicit
FP-exclusion sensitivity scenarios (both reviewers / either reviewer). Sampling
is over unique predictions, with annotation-comparison multiplicities included
in the expansion estimator. These scenarios are neither corrected ground truth
nor statistical confidence bounds. The objective, other-annotator-corroborated
FP result is reported separately and does not require human reviews.

## CPU timing and report generation

Stop the experiment queues before controlled CPU timing, then resume them afterward.
All three benchmarks use the same 50 tune images, one numerical thread, three
warmups and no preprocessing cache. Image IO and scoring are excluded.

```powershell
python -m scripts.benchmark --config configs/frozen_classic/baseline.yaml --out results/benchmark_baseline.json
python -m scripts.benchmark --config configs/frozen_classic/full.yaml --out results/benchmark_classical.json
python -m scripts.benchmark --config configs/unet_e7a_selected.yaml --checkpoint results/unet_e7a/best.pt --out results/benchmark_unet.json
python -m scripts.analyze_results
python -m scripts.build_report
python -m scripts.package_submission
```

After all automatic experiments finish and the PDF passes visual inspection,
`python -m scripts.export_evidence --require-complete --report output/pdf/final_report.pdf`
copies aggregate evidence, selected recipes and figures into versioned `docs/`
and `configs/`. Its manifest records source paths and SHA256 digests (text files
use UTF-8/LF normalization to survive Git line-ending conversion); raw data,
weights and review keys are not exported. Omit `--report --require-complete` to
export an explicitly incomplete aggregate snapshot during execution.

The analyzer requires completed E3 curves by default. `--allow-incomplete` is
only for a draft and explicitly marks missing points. The report includes only
measured extension results and leaves absent seeds, folds and human reviews pending.
Its optional `--contributors` argument accepts a JSON list of objects with
`name` and `contribution` fields. Render and inspect the PDF before submitting it.
